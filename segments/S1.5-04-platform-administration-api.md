## Acceptance

- Versioned REST noun routes cover current-tenant details and the listed Platform Core resources.
- Every route requires trusted identity, tenant context, and an exact server-side permission.
- Request bodies cannot select another tenant; repository scope comes only from trusted context.
- List operations are ordered, filtered where applicable, bounded, and cursor-paginated in PostgreSQL.
- Commands reject unknown/invalid fields with safe deterministic errors.
- Durable idempotent replay returns the original status/body; fingerprint mismatch returns conflict.
- Every successful command appends immutable, tenant-chained audit evidence atomically.
- Number allocation is unique under concurrent calls and idempotent replay.
- RLS and application checks deny manipulated cross-tenant IDs.
- Forward/rollback evidence covers the new control tables and populated rollback refusal.
- Canonical OpenAPI, route registry, generated client, and backend regression remain synchronized.
