Seven design decisions/ambiguities resolved and reported (all documented
in full, with reasoning, in `app/finance/reporting.py`'s module docstring
and `docs/evidence/S2.3-verification.txt`): (1) the design doc's proposed
report routes violate the locked REST_PATH contract regex -- resolved with
flat snake_case nouns, same precedent as S2.1/S2.2's own route renames;
(2) no async worker infrastructure exists anywhere in this codebase, so
Consolidated Statement jobs genuinely persist a queued/running/completed/
failed state machine but execute synchronously in-request before
responding -- disclosed, not hidden, and forward-compatible with a real
worker later; (3) Cost of Sales/OpEx and Operating/Investing/Financing
sub-classification aren't representable in S2.2's locked 5-account-type
schema, so P&L and Cash Flow report the coarser split with an explicit
`classification_note` field in the API response itself; (4) the Balance
Sheet equation is made to hold exactly (a mandatory invariant) via the
standard "Current Year Earnings" synthetic equity line every real
double-entry system uses when it defers period-close sweeps -- not a
fabricated number, the exact Assets = Liabilities + Equity + Revenue -
Expense identity double-entry bookkeeping already guarantees; (5)
Consolidated Statements resolve against an exact named `ConsolidationGroup`
version id (no lineage/effective-date auto-resolution, since S2.2's schema
has no lineage key); (6) "organization-level restriction" is implemented as
real data-boundary validation (unknown/foreign company_id returns empty,
never a leak) rather than a second RBAC dimension S1.2 doesn't have; (7)
`intercompany_profit` elimination rules are accepted and listed as
`unapplied_rules` in the consolidated response, not silently faked, since
no profit-in-inventory data is modeled anywhere in S2.2.
