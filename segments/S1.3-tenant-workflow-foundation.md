  and TenantPolicy are implemented (migration `0004_module_policy`), with
  21 more passing tests (8 unit, 9 integration, 4 migration; cumulative 137

  Data models table (C3's "modules... policy configuration" responsibility
  was previously prose-only). **Item 1 of 3 (tenant configuration model) is
  now complete.**
- Workflow definition engine (item 2), completed 2026-08-07 (third pass):
  `WorkflowDefinition`/`WorkflowStep` (DAG validation via stdlib `graphlib`,
  covering both next- and exception-step edges) and `ApprovalInstance`
  (injected-clock SLA status, version/entry-step binding at start) are
  implemented in `app/workflow/`, with `WorkflowApprovalService` reusing
  S1.2's authorization gate and audit writer exactly -- no second auth or
  audit mechanism -- and denying self-approval before authorization even
  runs. Migration `0005_workflow_foundation`. 32 more passing tests (17
  unit, 11 integration, 4 migration; cumulative 169 across the whole test
  suite). **Item 2 of 3 is now complete.**
- Admin setup flow (item 3), completed 2026-08-07 (fourth pass): `SetupDraft`
  (`app/platform/setup.py`) bundles tenant/organization-unit/fiscal-calendar/
  currency/module/policy/workflow-definition setup into one draft, validated
  by constructing the real domain objects already used everywhere else --
  invalid items never reject the request, they become `field_errors` on the
  saved draft (preserve-on-failure, as required). `SetupDraftService`
  (`app/platform/setup_service.py`) drives draft -> approved -> activated,
  reusing S1.2's authorization gate and audit writer exactly. Activation
  coordinates platform + workflow repositories in one transaction (they
  share a connection): any failure rolls back everything, the draft stays
  `approved`, never partially `activated` -- proven by a dedicated test.
  Exposed as three routes (`POST/GET /api/v1/platform/setup_drafts`,
  `POST /api/v1/platform/setup_draft_decisions`,
  `POST /api/v1/platform/setup_draft_activations`) using underscores, not
  the segment's own informal hyphenated locator note -- the codebase's
  actual enforced route-shape regex (`tests/contract/test_openapi_contract.py`)
  only allows `[a-z0-9_]`, so the informal note was corrected to match the
  real constraint, not the other way around. `contracts/openapi-v1.json`
  extended to match. 40 more passing tests (13 unit, 22 integration,
  5 migration; cumulative 209 across the whole test suite). One real bug
  (S1.3-F01, resolved) was found and fixed by these tests: a denied
  internal-gate check was leaking as a raw 500 instead of 403.
  **Item 3 of 3 is now complete. S1.3 is closed.**
