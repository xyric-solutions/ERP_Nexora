## Why this is one buildable unit
Added 2026-08-06 (`accepted-improvements.md` I-017) to close a gap identified during the Stage 3 Engineering Blueprint review: the locked 12-segment plan built a full API/security platform (S1.1-S1.3) but scoped no client to consume it. Routing, auth flow, generated API client, base layout, and shared component conventions (forms, tables, theme, error boundary) are one verifiable shell that every later module UI extends. It can be proven against the existing OpenAPI contract and a seeded backend without any business-module UI existing yet. Sequenced after S1.1-S1.3 in Phase 1's build order (`phase-plan.md`) since it depends on the API shell (S1.1) and identity (S1.2) being live; it does not depend on S1.3's tenant/workflow admin flows.
