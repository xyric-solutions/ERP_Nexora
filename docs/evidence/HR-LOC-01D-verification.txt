Scope delivered
---------------
- Country-neutral, effective-dated company legal profile, statutory
  registration, payroll configuration, and localization activation services.
- Read-only country, jurisdiction, legal-entity, localization-pack, and pack-
  version catalogs.
- Company-scoped HTTP APIs with exact permissions, idempotent commands,
  transactional immutable Security audit evidence, and PostgreSQL RLS.
- Setup-draft support for all four company-localization sections in the same
  transaction as company creation.
- Explicit localization context separating jurisdiction identification, pack
  availability, approved/active pack state, and statutory compliance. This
  slice always reports statutory_compliance_status=not_assessed.
- Existing companies retain legacy_unlocalized behavior; newly created
  companies retain localization_required behavior from HR-LOC-01A.

- Existing migration forward/idempotency/clean rollback/reapply and populated
  rollback-refusal coverage passed in the canonical migration suite and both
  live PostgreSQL suites.

Security and policy result
--------------------------
- Catalog reads require platform.localization.read.
- Company reads/manages use the approved company-scoped permissions.
- Localization creation/action uses platform.localization.activate.
- HTTP authorization and the service command gate both carry company_id;
  tenant isolation is additionally enforced by forced RLS and composite
  tenant/company references.
- Registration secret_reference may be persisted as an external secret handle
  but is never returned in API/setup snapshots or audit state.
- Production active transition is blocked by code policy with no environment
  switch. The test-only policy is explicit in-process and is used solely with
  synthetic XX fixtures.
- Active transition also requires compatible approved/active pack evidence,
  a controlled importer release, complete effective dependencies, an approved
  legal profile, and an active payroll configuration.
- Selecting a country/jurisdiction never creates a compliance claim and never
  causes inferred jurisdiction selection.

Defect found and corrected during verification
----------------------------------------------
- The first full run exposed a demo-runtime compatibility defect: the new
  repository rejected the established autocommit connection and changed the
  shared row factory to dict_row. The constructor now supports the established
  explicit transaction boundary and preserves POSTGRES_ROW_FACTORY. The
  affected end-to-end test then passed 5/5, followed by a clean full run.
