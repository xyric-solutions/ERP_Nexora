- WorkflowStep/WorkflowDefinition: entry_step_id must reference a defined
  step; every next_step_id/exception_step_id must reference a defined step
  or be null (terminal); duplicate step ids rejected; cycles rejected via
  stdlib graphlib.TopologicalSorter over both next- and exception-edges,
  including self-referencing steps and cycles that only exist through the
  exception path, not just the happy path -- a diamond-shaped (non-cyclic)
  graph is correctly allowed (9 unit tests).
- ApprovalInstance.sla_status(now) derives on_track/due/breached from an
  injected instant, never a wall-clock call inside domain logic; due_at
  before started_at is rejected at construction; a decided instance
  (approved/rejected) reports not_applicable rather than a stale status
  (6 unit tests).
- Repository: workflow definition creation requires the tenant to exist;
  at most one `active` version per tenant/module/trigger, enforced by a
  partial unique index, same pattern as S1.3's TenantPolicy; approval
  instance creation requires an active definition, the matching version,
  and that it starts at the definition's entry step (4 integration tests).
- WorkflowApprovalService reuses S1.2's SecurityCommandAuthorizationGate
  and audit writer directly -- no second authorization or audit mechanism.
  Self-approval (actor == requester) is denied before the authorization
  check even runs, so a misconfigured permission can never allow it. The
  default reject-all gate denies even a correctly-permissioned approver
  until a real gate is wired in, matching S1.2's secure-default discipline.
  Approve/reject correctly advance to next_step_id/exception_step_id, or
  complete the instance at a terminal (null) step; every decision writes
  one audit event via the same former SecurityRepository.append_audit used
  by S1.2 (7 integration tests).
