Validation controls
- Exact schema and file inventory; UTF-8; duplicate-key, symlink, size, depth,
  unexpected-file, float/non-finite, unsafe text, and unknown-field rejection.
- System publisher scope only; `approved` lifecycle intent only; reviewer and
  approver separation; UTC approval timeline; valid legal effective ranges.
- Controlled country/jurisdiction lookup; exact approved immutable parent
  versions; same-country ancestor stacking; legal-range coverage; cycle and
  duplicate rejection.
- Allow-listed rule types and stacking operations; typed deterministic
  configuration; declarative applicability; AST-limited arithmetic formula;
  no Python/module/script/callable/import/eval/exec content.
- Every rule cites a declared authoritative source and carries positive,
  boundary, and non-applicable reviewed vectors.
- Approved effective overlaps require explicit same-identity pack and rule
  supersession chains.
- Synthetic artifacts import only in `test`. Production-classified artifacts
  remain closed unless the explicit deployment gate is enabled after governance
  approval; no production artifact ships.

Security/RBAC/privacy review
- Actors: migration owner registers/revokes; dedicated publisher validates and
  inserts controlled global evidence; ordinary application/tenant roles have no
  publisher path. There is no anonymous/user HTTP surface.
- Publisher registration rejects superuser, owner, role-creator, database-
  creator, replication, RLS-bypass, inherited-role, schema-create, or unrelated
  table privileges. Every dry-run/import rechecks privilege scope.
- Publisher can select controlled global catalogs and insert pack/rule/vector/
  release rows only. It cannot read tenant HR/payroll tables, update/delete
  approved evidence, manage its own registration, or mutate country,
  jurisdiction, or legal-entity reference catalogs even if mistakenly granted
  direct table access.
- Immutable release evidence records database-derived publisher identity and
  hashes/counts, not DSNs, source documents, tenant data, payroll data, or
  request bodies. CLI/database errors do not print credentials.
- Application runtime receives no publisher DSN. `.env.example` and operator
  docs state this separation explicitly.
