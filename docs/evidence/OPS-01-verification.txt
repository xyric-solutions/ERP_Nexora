OPS-01 DISTRIBUTED CONTROLS AND OBSERVABILITY - VERIFICATION
Date: 2026-09-25 Asia/Karachi
Status: READY FOR REVIEW WITH EXTERNAL OPERATIONS WAIVERS

IMPLEMENTED
- Required Redis production configuration, application-lifetime async client,
  fail-closed startup and PostgreSQL+Redis readiness.
- HMAC-SHA256 Redis keys that do not disclose raw tenant, actor or
  idempotency values.
- Atomic Lua fixed-window rate limiting shared across replicas.
- Lease/heartbeat Redis idempotency claims, fingerprint conflict detection,
  bounded wait, response replay and uncertainty-safe post-effect behavior.
- Dedicated-auth Prometheus metrics and provider-neutral OpenTelemetry server
  tracing with bounded route labels and privacy-minimized attributes.
- Production disables the legacy process-memory `/platform/resources`
  scaffold; development/reference composition retains it for compatibility.
- CI and disposable Redis/PostgreSQL production-composition verification.

SECURITY AND DATA-INTEGRITY REVIEW
- Remote plaintext redis:// configuration is rejected; rediss:// is required
  outside localhost.
- Redis outages return API_DISTRIBUTED_CONTROL_UNAVAILABLE without DSNs or
  internal diagnostics.
- Claims are released when the operation fails before returning, but are not
  released after a returned operation if response persistence fails.
- Redis coordinates transport retries only. Material ERP command services
  retain durable PostgreSQL idempotency because Redis and PostgreSQL cannot
  share one atomic transaction.
- Metrics and spans exclude authorization, cookies, request/response bodies,
  query strings, tenant IDs, actor IDs, correlation IDs and arbitrary paths.
- No generic ERP resource write is allowed to masquerade as durable production
  data in process memory.
