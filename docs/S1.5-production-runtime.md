# S1.5 Production Runtime

S1.5-03 introduces the production FastAPI process boundary. It owns the
PostgreSQL connection-pool and Redis client lifecycle and infrastructure probes, then mounts the
existing versioned Nexora ASGI API unchanged. The Demo/local entrypoint remains
`app.main:app` and is not a production deployment target.

## Required configuration

Provide these values through the deployment secret/configuration system. Do
not commit them to source control or place them in command-line arguments.

| Variable | Requirement |
|---|---|
| `NEXORA_DATABASE_DSN` | PostgreSQL connection string for a least-privilege application role; required |
| `NEXORA_CURSOR_SECRET` | Stable secret of at least 32 bytes; required and shared by all API replicas |
| `NEXORA_REDIS_DSN` | Redis URL shared by all API replicas; `rediss://` is required outside localhost |
| `NEXORA_REDIS_KEY_SECRET` | Stable HMAC secret of at least 32 bytes used to conceal control-key dimensions |
| `NEXORA_METRICS_BEARER_TOKEN` | Separate bearer secret of at least 32 bytes for `GET /metrics` |
| `NEXORA_DATABASE_POOL_MIN_SIZE` | Integer 1-100; default `1` |
| `NEXORA_DATABASE_POOL_MAX_SIZE` | Integer from the minimum through 100; default `10` |
| `NEXORA_DATABASE_CONNECT_TIMEOUT_SECONDS` | Integer 1-120; default `5` |
| `NEXORA_DATABASE_STARTUP_TIMEOUT_SECONDS` | Integer 1-120; default `15` |
| `NEXORA_DATABASE_ACQUIRE_TIMEOUT_SECONDS` | Integer 1-120; default `5` |
| `NEXORA_PASSWORD_AUTHENTICATION_ENABLED` | Boolean; default `false`. Set `true` only when the first-party credential flow is approved for the environment |
| `NEXORA_SESSION_SIGNING_SECRET` | Stable random value of at least 32 bytes; required when password authentication is enabled and shared by all API replicas |
| `NEXORA_REDIS_MAX_CONNECTIONS` | Integer 1-1000; default `20` |
| `NEXORA_REDIS_SOCKET_TIMEOUT_SECONDS` | Integer 1-120; default `2` |
| `NEXORA_REDIS_STARTUP_TIMEOUT_SECONDS` | Integer 1-120; default `10` |
| `NEXORA_RATE_LIMIT_REQUESTS` | Positive shared fixed-window request limit; default `120` |
| `NEXORA_RATE_LIMIT_WINDOW_SECONDS` | Positive window length; default `60` |
| `NEXORA_IDEMPOTENCY_LEASE_SECONDS` | Claim lease, minimum 3; default `30` |
| `NEXORA_IDEMPOTENCY_RESULT_TTL_SECONDS` | Replay retention not shorter than the lease; default `86400` |
| `NEXORA_IDEMPOTENCY_WAIT_SECONDS` | Bounded wait for an in-flight duplicate; default `5` |
| `NEXORA_OTEL_EXPORTER_OTLP_ENDPOINT` | Optional credential-free HTTP(S) OTLP trace endpoint |

The runtime refuses to construct without the PostgreSQL, cursor, Redis and
metrics configuration. It refuses startup unless PostgreSQL and Redis both
respond. Errors returned by probes and the startup wrapper do not include a
DSN, credential or infrastructure diagnostic.

## Migration and startup

Run schema migration as a separate deployment job with the migration-owner
role described in `docs/migrations/S1.5-platform-core-postgresql.md`. Do not
give the API role ownership or migration privileges.

Start the API through the application factory:

```powershell
python -m uvicorn app.production.application:create_application --factory --host 0.0.0.0 --port 8000
```

Use the orchestrator or reverse proxy for TLS termination, trusted proxy
configuration, worker/process management, and graceful replacement. The
production runtime does not auto-run migrations because multiple application
replicas must not race deployment ownership.

## Probes

- `GET /health/live` checks only that the API process is serving requests.
- `GET /health/ready` checks PostgreSQL with `SELECT 1` and Redis with `PING`.
- `GET /metrics` requires its dedicated bearer secret and exposes
  bounded-cardinality Prometheus metrics; it is not part of the public API.
- `GET /api/v1/platform/health` remains the existing public v1 API health
  resource and contract.

The two unversioned paths are infrastructure endpoints, are excluded from the
public OpenAPI document, return `Cache-Control: no-store`, and expose only a
component/status value. Readiness returns HTTP 503 after PostgreSQL or Redis loss;
liveness remains HTTP 200 so the orchestrator can distinguish replacement from
temporary dependency unavailability.

## Current boundary

The Platform PostgreSQL schema, adapter, administration service/API, and
FastAPI process/pool boundary exist. Unsupported business-domain repositories
are not wired to local fallback or in-memory persistence by the production factory;
their existing handlers retain secure deny/service-unavailable behavior.
PostgreSQL authorization and the opt-in credential/session path are implemented
by SEC-PG-01. OPS-01 supplies shared Redis rate limiting/idempotency and
provider-neutral Prometheus/OpenTelemetry instrumentation. Managed OIDC/SAML,
centralized revocation/service identity (Q-003) and the operational
cloud/KMS/backup/HA controls remain blocked. See
`docs/production-deployment-runbook.md`; this runtime must not be represented
as production-ready on its own.
