# S1.2 Security Baseline Migration

- Version: `0001`
- Adapter: Psycopg 3 PostgreSQL persistence
- Forward:
  `app/security/migrations/0001_security_baseline.forward.sql`
- Rollback:
  `app/security/migrations/0001_security_baseline.rollback.sql`
- Runner: `app/security/migrations.py`

Forward creates `user_account`, `role_policy`, `user_role_assignment`, and
`audit_event`, their tenant indexes/constraints, and audit update/delete
blockers in one explicit transaction. Role assignments use composite
tenant/record foreign keys. Applying an already-recorded migration is a no-op;
pre-existing unledgered security tables are treated as drift and fail.

Rollback is intentionally narrow. It drops the baseline only when all four
tables are empty. Once any account, policy, assignment, or audit evidence
exists, `MigrationRollbackBlocked` preserves the schema and data. Operational
rollback after use means disabling the writer/feature, revoking/deactivating
accounts or policy versions as applicable, and preserving audit records—not
running the destructive SQL file.

This migration proves data paths and reversibility for S1.2. It does not select
or emulate the production database, encryption, replication, backup, or
retention model.

Verify with:

```powershell
python scripts/verify.py migration
```
